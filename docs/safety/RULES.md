# RULES.md — Detection Catalog

**Status:** Living reference and audit trail. The authoritative rules live in `reclaim-detect` as data; this document mirrors them for humans. When a rule changes, this file and `CHANGELOG.md` must change in the same commit — deletion logic never changes silently (see ADR-008, THREAT_MODEL T8).
**Catalog version:** v1.1-draft
**Last updated:** 2026-08-17

---

## How to read this

Each rule has: an **ID** (stable), a **pattern** (what it matches), a **tier**, a **reclaim method**, a **rebuild cost**, and a **rationale**. Tiers and methods are defined below.

### Tiers
- **Safe** — known pure-junk, regenerable, low-stakes. May be pre-selected in the UI.
- **Probably-safe** — reclaimable but with a rebuild cost. Never pre-selected unless cheap; the cost is shown.
- **Unknown** — matches no rule. Surfaced with size + contents for manual review; never pre-selected. (Stage 2 adds AI explanation here.)
- **Never-touch** — protected. Shown locked; refused by the action layer.

### Reclaim methods
- **Move** — quarantine via same-volume move.
- **Command(x)** — invoke the tool's own cleanup command `x` (only if the tool is detected); else offer a careful Move.

### Rebuild cost
- **Cheap** — regenerates for free or near-free (caches that rebuild on next use).
- **Expensive** — costly to rebuild (re-download on metered links, long rebuilds, large model re-fetches). Never pre-selected; flagged in UI.

## 1. Dev project junk (Tier: Safe, Method: Move)

Project-local build artifacts. Safe to move when not locked by a running process/editor.

| ID | Pattern | Rebuild cost | Rationale |
|---|---|---|---|
| DEV-001 | `node_modules/` | Cheap* | Regenerated by `npm/yarn/pnpm install`. *Re-download cost on metered links. |
| DEV-002 | `target/` (Rust; dir containing/under a `Cargo.toml`) | Cheap | `cargo build` regenerates |
| DEV-003 | `dist/`, `out/` (sibling project marker: `package.json`, `Cargo.toml`, `build.gradle`/`build.gradle.kts`, `pyproject.toml`, `.csproj`/`.sln`); `build/` (sibling Gradle marker only: `build.gradle`/`build.gradle.kts`/`settings.gradle`) | Cheap | Rebuild output. `build/` is gated narrower than `dist`/`out` — it's too common a plain-source-folder name, and a general marker (esp. `Cargo.toml`) isn't enough: an extracted crate's own source tree under `~/.cargo/registry` has a genuine `Cargo.toml` sibling and ships its own `build/` module dir, which is source, not build output. No marker → Unknown, not Safe. |
| DEV-004 | `.next/`, `.nuxt/`, `.svelte-kit/`, `.turbo/` | Cheap | Framework build caches |
| DEV-005 | `__pycache__/`, `.pytest_cache/`, `.mypy_cache/` | Cheap | Regenerated on next run |
| DEV-006 | project `.gradle/` | Cheap | Re-downloaded/regenerated |
| DEV-007 | `bin/`, `obj/` (.NET, scoped to a project dir) | Cheap | Rebuild output |

**Guards for all DEV rules:** must not be under a protected root (→ Never-touch); must not have an open handle from a running process/editor (skip + report holder); presence of a project marker (`package.json`, `Cargo.toml`, `.csproj`, etc.) increases confidence.

## 2. Managed-store caches (Tier: Probably-safe, Method: Command)

Prefer the tool's own cleanup; raw deletion under a lock can corrupt state (ADR-009). Detect the tool before offering the command.

| ID | Store | Command | Rebuild cost | Never touch |
|---|---|---|---|---|
| STORE-001 | npm | `npm cache verify` → `npm cache clean --force` | Expensive | — |
| STORE-002 | yarn (classic) | `yarn cache clean` | Expensive | — |
| STORE-003 | yarn (berry) | `yarn cache clean --all` | Expensive | — |
| STORE-004 | pnpm | `pnpm store prune` | Expensive | — |
| STORE-005 | pip | `pip cache purge` | Expensive | — |
| STORE-006 | cargo | `cargo cache --autoclean` (or move `~/.cargo/registry/{cache,src}`) | Expensive | **`~/.cargo/bin`, credentials** |
| STORE-007 | Gradle (global) | move `~/.gradle/caches` | Expensive | — |
| STORE-008 | NuGet | `dotnet nuget locals all --clear` | Expensive | — |
| STORE-009 | Go | `go clean -cache` / `-modcache` | Expensive | — |

**Note:** modern Cargo auto-GCs the *global* cache (extracted >1 month, downloaded >3 months, checked daily) but does **not** clean project `target/` — that's DEV-002.

## 3. Docker (special handling)

| ID | Target | Action | Tier | Rationale |
|---|---|---|---|---|
| DOCKER-001 | dangling images + build cache | `docker system prune` (measure with `docker system df`) | Probably-safe | Reclaims safely; does **not** touch volumes by default |
| DOCKER-002 | **named/anonymous volumes** | **surface only** — never auto-act | **Unknown — contains data** | Volumes hold databases/state; `--volumes` = permanent loss (THREAT_MODEL T11). Hard-blocked in the runner. |

**Absolute rule:** `--volumes` is never passed automatically and never a default/pre-selected action.

| ID | Pattern | Rebuild cost | Notes |
|---|---|---|---|
| WIN-001 | `%TEMP%`, `C:\Windows\Temp` | Cheap | Skip in-use files |
| WIN-002 | Thumbnail cache | Cheap | Regenerates |
| WIN-003 | Shader cache (GPU) | Cheap | Regenerates |

**Explicitly excluded from v1:** WinSxS / component store. Requires `DISM /StartComponentCleanup` + admin; raw deletion corrupts the OS. Deferred to Stage 3. Never a candidate in v1.

## 5. Never-touch (the denylist)

Not a "rule" so much as the floor every rule sits above. Enforced in `reclaim-core::is_protected`, checked in detection and again in the action layer (ADR-004).

- `C:\Windows` (esp. `System32`, `WinSxS`), Program Files install dirs
- User `Documents`, `Desktop`, `Pictures`, `Videos`, `Music`
- `%AppData%` / `%LocalAppData%` roots (saves, config, `.env`, local DBs)
- Recycle Bin; System Restore / shadow storage
- **Any path under an active cloud-sync root**
- **Docker volumes**

Anything resolving under these is Never-touch regardless of any rule above.

## Rule-change policy

1. **Never silently.** A change to any rule (add/remove/retier) requires a `CHANGELOG.md` entry and a bump to the catalog version.
2. **Consent for updates.** An update that changes what's removable requires explicit user consent, not a background push (ADR-005/008).
3. **Auditable.** Every action records the rule ID + catalog version that decided it (`audit_log.decided_by`), so past behavior is reconstructable.
4. **Conservative by default.** When unsure whether something is pure junk, it is **Unknown**, not Safe. Safe is reserved for patterns that are regenerable with near-certainty.

## Adding a rule (checklist)

- [ ] Pattern is specific enough that false positives are near-zero.
- [ ] Correct tier — if there's *any* data-loss doubt, it's Unknown, not Safe.
- [ ] Correct method — managed store ⇒ Command; project artifact ⇒ Move.
- [ ] Rebuild cost set; Expensive items never pre-selected.
- [ ] Guards: protected-root check, open-handle check.
- [ ] Golden test fixture added (`TESTING.md`).
- [ ] `CHANGELOG.md` entry + catalog version bump.
